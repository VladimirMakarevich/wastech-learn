# Kafka consumer lag and OOM

## Question

[High-load] A Kafka consumer lags 2M messages and its pods get OOM-killed; producers are healthy. What do you change first?

## Answer

Bound in-flight work: a smaller `max.poll.records` and a bounded processing queue; then scale consumers up to the partition count.

## Rubric

- (!) Bound in-memory work: batch size or a bounded queue
- (!) Scale consumers, but not beyond the partition count
- Measure processing time per message
- More memory alone only delays the next OOM
