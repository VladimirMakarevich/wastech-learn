# Бэклог и нерегулярный ритм

Пользователь повторяет нерегулярно. Система не должна наказывать за пропуски: ни стены из 300 карточек, ни счётчика пропущенных дней. FSRS сам учитывает реальный интервал. Review item, вспомненный после долгой паузы, получает большой прирост stability. Поэтому задача системы — разумно дозировать нагрузку.

## Что считается бэклогом

**Бэклог** — review items, у которых `due` раньше начала текущего дня. Нагрузка оценивается в минутах по медиане собственного времени ответа (`durMs`) для каждого типа карточек. Пока данных нет, используются оценки по умолчанию: 8 с для `basic`, 20 с для `why` и `compare`, 45 с для `scenario`.

## Политика

| Правило | Значение по умолчанию | Принцип |
| --- | --- | --- |
| Дневной лимит повторений | 150 review items или `sessionMinutes` × 3 | LP-02 |
| Пауза новых карточек | Если бэклог больше `2 × reviewsPerDay`, новые = 0 | LP-11 |
| Возврат новых | Когда бэклог меньше `reviewsPerDay`; первые 3 дня — половина лимита | LP-13 |
| Порядок при бэклоге | По возрастанию R: сначала то, что вот-вот забудется (итог Q-01) | LP-02 |
| Learning steps | Всегда первыми, вне лимитов | LP-11 |
| Leech при бэклоге | Не показываются, ждут fix list | LP-13 |

Порядок выбран симуляцией ([Q-01](../risks-and-questions.md)): `wastech-learn simulate` проигрывает 90 дней ежедневной практики, 14 дней перерыва и сессии по 15 минут без новых карточек, по 20 сидов на каждый порядок. Ответы — с вероятностью R модели, лимиты — из golden `learn.config.json`.

| Колода | По возрастанию R | По убыванию R | Относительная просрочка |
| --- | --- | --- | --- |
| 300 карточек, бэклог ≈ 90–115 | медиана 3 сессии, ≤5 дней в 19 из 20 | 4, 20 из 20 | 3, 20 из 20 |
| 450 карточек, бэклог ≈ 150–180 | 4, 17 из 20 | 5, 17 из 20 | 4, 19 из 20 |
| 600 карточек, бэклог ≈ 220–250 | 5, 11 из 20 | 6, 4 из 20 | 6, 8 из 20 |

По возрастанию R и по относительной просрочке разбирают бэклог одинаково часто (47 из 60 прогонов), но у первого медиана лучше на большой колоде; доля вспомненного у всех трёх около 87%. Критерий MVP выполняется до ~450 карточек; на 600 медиана ровно 5 дней. Порядок — параметр очереди, его можно сменить без правки кода хостов.

Если варианты одной карточки или карточки одной `idea` конкурируют за день, показывается тот, кто ждёт дольше: иначе близнец, который каждый день уходит в relearning, неделями хоронит соседа.

## Режим «5 минут»

- Запускается с главной одной кнопкой. Длительность настраивается: 5, 10 или 15 минут.
- Берёт review items по порядку очереди, пока оценка времени не достигнет лимита.
- Когда время вышло, текущая карточка дорешивается, и сессия завершается экраном итогов. Остальное ждёт.
- Новые карточки в этом режиме не показываются.

## План возврата после перерыва

Если после последней сессии прошло больше 3 дней, главная показывает спокойный план вместо цифры долга:

```text
С возвращением! Накопилось 180 карточек ≈ 45 мин.
Предлагаю разобрать за 3 дня по 15 минут — новые карточки пока на паузе.
[ 5 минут ]  [ 15 минут ]  [ Вся очередь ]
```

- Формулировки без вины: никаких «вы пропустили 14 дней» и «серия прервана» ([interaction](../ux/interaction.md)).
- Расписание не сдвигается искусственно. FSRS сам корректирует интервалы по фактическому ответу.

## Квиз в чате при бэклоге

`learn-quiz` в Claude Code берёт ту же очередь, но батчами по 5–10 карточек, чтобы не упереться в лимиты подписки. Он начинает с одной строки статуса: «Due 42 ≈ 12 мин, бэклог — новые на паузе» ([tutor-and-grading](../ai/tutor-and-grading.md)).

## Напоминания

- **MVP:** счётчик «N карточек ≈ M мин» на главной; статус в начале `learn-quiz`. Оба показываются, только когда пользователь сам пришёл.
- **Later:** пуш-уведомления в мобильном приложении, не чаще раза в день, в выбранное время, с текстом «≈ 5 минут на сегодня». Стриков нет.
- Heatmap активности по умолчанию выключен. Вместо него показывается прогноз нагрузки на 7 дней.

## Проверка политики

- Симуляция: синтетический журнал с перерывом в 14 дней. Критерий MVP — бэклог разбирается сессиями по 15 минут не дольше чем за 5 дней без новых карточек ([roadmap](../roadmap.md)).
- Тесты свойств очереди: лимиты не превышаются, siblings не встречаются в один день, learning steps всегда первые (NFR-14).
