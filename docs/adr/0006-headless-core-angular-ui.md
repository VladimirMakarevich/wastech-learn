# ADR-0006: Headless TS-ядро + desktop-first UI на Angular и CDK

## Контекст

Сейчас повторение идёт в десктоп-браузере, в будущем нужно мобильное приложение. UI нужен на ru, en и pl. Пользователь — senior в Angular и .NET. Исследование стека рекомендовало Astro + island + PWA, архитектурное ревью — Ionic-шаблон `wastechlab-mobile-template` (Ionic Angular + Capacitor, offline-first SQLite, i18n с плюралами и проверкой паритета ключей). [Кликабельный прототип](../../prototypes/desktop-ui/README.md) показал, что внешний вид задаёт собственная система «Evening Glass» ([DESIGN.md](../../DESIGN.md)), а не UI-кит: свои переключатели, степперы, сгруппированные списки, поле точек памяти, стекло только у плавающего хрома.

## Решение

- Вся логика — в TypeScript-пакетах `core`, `srs` и `content-fs` ([components](../architecture/components.md)). FSRS и очередь работают в клиенте.
- UI — desktop-first Angular: standalone-компоненты, signals, без zone.js. Angular CDK даёт только поведение: focus trap, a11y, overlay. Angular Material и его тема не подключаются.
- Вид — Evening Glass: токены и стили переносятся из прототипа, источник правды — DESIGN.md.
- i18n переносится из `wastechlab-mobile-template`: сервис, pipe, типизированные словари ru/en/pl, проверка паритета ключей и аудит литералов в шаблонах. Плюралы — через `Intl.PluralRules`, таблица шаблона остаётся тестом.
- Шаблон — донор отдельных частей, а не основа: Firebase, auth, OpenAPI-клиент, NgModules, zone.js и Ionic не переносятся.
- Мобильная версия (фаза 2) — Capacitor и SQLite поверх того же приложения. Sheet и закреплённая панель решения делаются на CDK; `@ionic/core` подключается точечно, только если отдельный компонент окажется дорогим.
- UI получает контент из пререндеренного content bundle, а состояние — только через `ReviewStore`.

## Альтернативы

- **Ionic-шаблон как основа.** Готовые мобильные жесты, sheets и переходы. Но компоненты в shadow DOM стилизуются через `::part` и переменные, скроллом владеет `ion-content` — Evening Glass пришлось бы переносить через переопределения. На десктопе, основном сценарии, Ionic слабее, а из шаблона пришлось бы удалять Firebase, auth и OpenAPI.
- **Astro + island + PWA.** Главный плюс — рендер контента при сборке — уже даёт `core`. Экраны в основном интерактивные, i18n пришлось бы строить заново, на мобильном — риски PWA на iOS.
- **Angular + ASP.NET Core API.** Родной стек, но второй рантайм, а логика FSRS и парсинга всё равно нужна в TS (mdlint, ts-fsrs, MCP).
- **Плагин Obsidian.** Ограничен API Obsidian, мобильная синхронизация через obsidian-git нестабильна.

## Последствия

- Качество рендера не хуже Astro: HTML пререндерит `core` (Shiki, KaTeX, SVG, sanitize).
- Мобильные компоненты фазы 2 (sheet инспектора, закреплённая панель, жесты) пишутся самостоятельно — [R-11](../risks-and-questions.md).
- Инструменты UI-тестов выбираются в M4.
- Ядро остаётся независимым от UI, поэтому замена UI возможна без изменения данных.
- 2026-11-25 статус возвращался в `proposed`: пользователь не был уверен, что мобильный Ionic-шаблон подходит основой для десктопа. 2026-11-26 после ревью прототипа принят desktop-first Angular + CDK, Ionic-шаблон перешёл в альтернативы ([Q-13](../risks-and-questions.md)).
