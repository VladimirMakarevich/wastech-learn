# ADR-0007: Фаза 1 — локальный Hono-сервер и кэш в `node:sqlite`

## Контекст

В MVP пользователь работает с одним или двумя компьютерами, хостинга нет, данные лежат в git. Приложение в браузере должно читать контент и дописывать журнал в файлы контент-репозитория. Браузер сам по себе писать в файлы надёжно не может.

## Решение

- `wastech-learn serve --content <path>` поднимает Hono на localhost и открывает браузер.
- Сервер отдаёт content bundle и журнал, принимает события (`POST /events`, идемпотентно по `event.id`) и дописывает их в `reviews/<device>/web-YYYY-MM.jsonl`.
- Watch за `content/**` и `reviews/**`: инкрементальная пересборка, уведомление UI через SSE.
- Кэш replay — `node:sqlite` (встроен в Node 24) в `.cache/`.

## Альтернативы

- **Статическое приложение + File System Access API.** Работает только в Chromium, каждый раз нужен доступ к папке, неудобно.
- **Только IndexedDB и экспорт.** Журнал не попадает в git автоматически, легко потерять данные.
- **Electron или Tauri.** Тяжело для MVP, а Capacitor всё равно понадобится для мобильной версии.

## Последствия

- Нужно запускать команду перед сессией. Позже — автозапуск или ярлык (Q-11).
- Сервер слушает только `127.0.0.1`, без аутентификации.
- Тот же `ReviewStore` в фазе 2 заменяется облачным, UI не меняется.
- 2026-11-27: кэш replay в `node:sqlite` в фазе 1 не делается — replay, очередь и метрики считает клиент ([ADR-0015](0015-session-package.md)).
- 2026-11-27: сервер приложения пишет статус и удаляет карточки, коммитит и синхронизирует контент-репозиторий через git ([ADR-0017](0017-app-server-writes-and-git.md)).
