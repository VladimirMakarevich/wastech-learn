# ADR-0006: Headless TS-ядро + UI на Angular/Ionic

## Контекст

Сейчас повторение идёт в десктоп-браузере, в будущем нужно мобильное приложение. UI нужен на ru, en и pl. Пользователь — senior в Angular и .NET и просил выбрать стек по итогам исследования. Исследование стека рекомендовало Astro + интерактивный island + PWA. Архитектурное ревью указало на минусы PWA: iOS очищает storage, пуш ограничен, для нативной версии пришлось бы переписывать UI. У пользователя есть `wastechlab-mobile-template` (Ionic Angular + Capacitor, offline-first SQLite, i18n ru/pl с плюральными формами и проверкой паритета ключей).

## Решение

- Вся логика — в TypeScript-пакетах `core`, `srs` и `content-fs` ([components](../architecture/components.md)). FSRS и очередь работают в клиенте.
- UI — Angular + Ionic на основе `wastechlab-mobile-template`: один код для десктоп-веба сейчас и Capacitor-приложения потом. Firebase, OpenAPI-клиент и auth из шаблона удаляются, добавляется широкая десктопная компоновка.
- UI получает контент из пререндеренного content bundle, а состояние — только через `ReviewStore`.

## Альтернативы

- **Astro + island + PWA.** Отличный рендер контента при сборке и меньше кода на старте. Но на мобильном нужна была бы PWA (риски iOS) или переписывание. i18n пришлось бы строить заново, Angular-islands поддерживаются плохо.
- **Angular + ASP.NET Core API.** Родной стек, но второй рантайм, а логика FSRS и парсинга всё равно нужна в TS (mdlint, ts-fsrs, MCP).
- **Плагин Obsidian.** Ограничен API Obsidian, мобильная синхронизация через obsidian-git нестабильна.

## Последствия

- Качество рендера не хуже Astro: HTML пререндерит `core` (Shiki, KaTeX, SVG, sanitize).
- Нужно адаптировать шаблон: десктопная компоновка, удаление лишних интеграций.
- Ядро остаётся независимым от UI, поэтому замена UI возможна без изменения данных.
