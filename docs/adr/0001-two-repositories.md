# ADR-0001: Два репозитория - фреймворк и приватный контент

## Контекст

В системе два вида данных с разной жизнью. Код фреймворка (ядро, приложение, MCP, skills) можно когда-нибудь открыть. Знания пользователя и история повторений приватны и растут годами. У пользователя уже есть такое разделение: `wastime-app` и `wastime-app-content`.

## Решение

- `wastech-learn` - фреймворк: документация, пакеты, приложение, CLI, MCP-сервер, skills, шаблоны, пресет mdlint.
- `wastech-learn-content` - приватный репозиторий: `content/`, `inbox/`, `journal/`, `reviews/`, конфиги.
- Фреймворк подключается к контенту по пути (локальный сервер, MCP, CLI с `--content <path>`) и через зафиксированные версии пакетов и skills.

## Альтернативы

- **Один репозиторий.** Проще на старте, но тогда нельзя открыть фреймворк, не открыв знания. История коммитов смешивает код и повторения.
- **Контент как git submodule.** Лишняя сложность в повседневной работе, а submodule плохо дружит с ИИ-агентами.

## Последствия

- Пресет mdlint и skills синхронизируются по версиям: `skills-lock.json`, копия пресета (Q-04).
- Журнал повторений не попадает в публичную историю.
- В Claude Code сессия захвата открывается в контент-репозитории. Фреймворк там доступен через MCP и skills.
