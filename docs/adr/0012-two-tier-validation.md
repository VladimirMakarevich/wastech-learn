# ADR-0012: Двухуровневая валидация — mdlint + `check`

## Контекст

Размер и структуру карточек, summary и документов нужно жёстко контролировать, чтобы контекст не разрастался. `wastech-mdlint` умеет бюджеты размера (SIZE-001), front matter (FM-001), секции (SEC-001/002), ссылки и картинки (REF), заглушки и declarative `custom`. Но он не считает слова в секции, не сравнивает front matter между файлами и по своему дизайну не исполняет пользовательский код.

## Решение

- **Уровень 1 — wastech-mdlint** с пресетом для контента ([mdlint-policy](../quality/mdlint-policy.md)). Работает в MCP `validate`, в hook Claude Code, в CI и в редакторе.
- **Уровень 2 — `wastech-learn check`** (пакет `core`): слова в вопросе и ответе по типу, пропуски cloze, рубрика, длина кода, уникальность `id`, свежесть SVG, ссылка карточки на summary, крупная правка `active`-карточки.
- MCP-инструменты не пишут файлы, пока оба уровня не пройдены.

## Альтернативы

- **Расширять mdlint правилами под карточки.** Смешивает универсальный линтер с доменом обучения. Code plugins в mdlint намеренно не поддерживаются.
- **Только `check`.** Пришлось бы дублировать готовые проверки ссылок, размеров и front matter.

## Последствия

- Два инструмента в CI, но каждый отвечает за своё.
- Пресет mdlint копируется в контент-репозиторий, синхронизация по версиям (Q-04).
- Предложения, полезные всем пользователям mdlint (например, cross-file уникальность front matter), можно отправить upstream в wastech-mdlint.
