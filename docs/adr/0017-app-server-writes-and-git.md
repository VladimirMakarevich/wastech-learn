# ADR-0017: Сервер приложения пишет контент и запускает git

## Контекст

По [ADR-0007](0007-local-server-phase-1.md) локальный сервер только читает контент и дописывает журнал. Отправлять оценки и правки на другой компьютер владелец ходит в терминал (`git add`, `commit`, `pull --rebase`, `push`), а убрать карточку из очереди может только правкой файла или через MCP. Спека [app-sync-and-cards](../tasks/app-sync-and-cards/index.md) переносит это в приложение: индикатор незакоммиченного, кнопки «Синхронизировать» и «Получить», архив и удаление карточек, архив темы. Сервер впервые меняет Markdown и запускает внешнюю программу — это новая граница хоста.

## Решение

- Логика git и новых записей — в `content-fs` (модуль `git/`, `deleteCard`, `restoreCard`, `setTopicStatus`); сервер только вызывает их, как MCP. Записи идут через тот же путь с проверкой `validateOverlay` и сверкой файла, что у MCP.
- Git запускается дочерним процессом (`spawn("git", ["-C", root, …])`) без оболочки, с фиксированным набором аргументов, `GIT_TERMINAL_PROMPT=0`, таймаутом (60 с для сети, 10 мин для локальных шагов с хуками), по истечении которого git сначала просят остановиться и только потом убивают, и `ssh -o BatchMode=yes`, если у владельца не задан свой `core.sshCommand`, `GIT_SSH_COMMAND` или `GIT_SSH`. Сообщение коммита — отдельный аргумент после `-m`; пути идут через стандартный ввод (`--pathspec-from-file`) с пометкой `:(literal)`.
- «Синхронизировать»: `git add --all -- content reviews inbox` → `commit` (если есть что) → `pull --rebase` с autostash → `push`. «Получить» — только pull. Конфликт откатывается `rebase --abort`; хуки владельца не отключаются.
- Одна операция за раз: очередь в процессе сервера для записи контента и git; чужой процесс узнаётся по `index.lock` и сверке файла.
- Сеть открывает только git и только по нажатию; ключи и пароли сервер не видит: доступ к удалённому — ssh-agent или credential helper владельца.

## Альтернативы

- **Git в `server`.** Логика в хосте нарушает headless-правило; MCP или CLI не смогли бы её переиспользовать.
- **`isomorphic-git`.** Новая зависимость и поведение, отличное от git владельца (хуки, ssh, credential helper).
- **Оставить терминал.** Задача владельца — не открывать терминал ради ежедневной отправки оценок.

## Последствия

- Сервер меняет файлы `content/` и создаёт коммиты от имени владельца; правила локального сервера в [.rules/security.md](../../.rules/security.md) расширены.
- В коммит синхронизации попадают только `content/`, `reviews/`, `inbox/`; остальное владелец коммитит сам.
- Запрос пароля не может подвесить сервер: git завершается с ошибкой, приложение просит выполнить команду в терминале.
- Межпроцессной блокировки нет: одновременная запись MCP и приложения ловится сверкой файла, а не замком.
