# ADR-0003: Append-only журнал событий для каждого устройства и writer

## Контекст

Состояние повторений меняется при каждом ответе. Если писать его в Markdown, как делает Obsidian Spaced Repetition, появляется шум в git, конфликты и давление на бюджеты mdlint. Состояние должно синхронизироваться между устройствами без сервера (фаза 1), переживать смену модели FSRS и служить входом оптимизатору.

## Решение

- События пишутся в JSONL: `reviews/<device>/<writer>-YYYY-MM.jsonl`. Строки только дописываются.
- Состояние — это результат replay журнала через планировщик. Кэш (`node:sqlite`) производный и лежит в `.gitignore`.
- Отмена — событие `undo`. Дубли отсекаются по `id` события (ULID).
- В каждом событии записаны `sched` (версия планировщика) и `contentHash`. Формат описан в [review-log.md](../content/review-log.md).

## Альтернативы

- **Состояние inline в Markdown.** Diff-шум, конфликты, лимиты mdlint.
- **Sidecar JSON на карточку.** Изменяемое состояние даёт конфликты, истории нет.
- **SQLite в git.** Бинарный файл не мержится.
- **Только IndexedDB.** Данные заперты в одном браузере.

## Последствия

- Git-merge не даёт конфликтов: каждый writer пишет свой файл. Для подстраховки задан `merge=union`.
- Смена модели или весов — это replay, история не переписывается.
- Нужен быстрый replay: NFR-05 требует меньше 5 с на 50k событий.
- Журнал растёт примерно на 4.5 MB в год. Это приемлемо, но со временем понадобится снапшот (Later).
