# Правила формулировки карточек

Правила для ИИ, который предлагает кандидатов, и для пользователя, который их правит. Источники: Wozniak (20 rules of formulating knowledge), Matuschak (How to write good prompts), Nielsen (Augmenting long-term memory). Автоматическую часть проверяют mdlint и `wastech-learn check` ([mdlint-policy.md](../quality/mdlint-policy.md)).

## Правила

1. **Сначала понять, потом запоминать.** Карточки появляются после brain dump, а не вместо него.
2. **Одна карточка - одна мысль.** Если в ответе «и», «а также» или список, карточку стоит разбить.
3. **Префикс контекста.** Вопрос начинается с контекста в квадратных скобках: `[.NET 8 GC]`, `[Angular signals]`, `[pl: Dopełniacz]`. Это снимает интерференцию похожих тем.
4. **Однозначный ответ.** Если правильных ответов несколько, вопрос просит «главный» или «один».
5. **Без вопросов «да/нет».** Шаблоны `Верно ли…`, `Можно ли…`, `Является ли…`, `Is…`, `Does…`, `Can…` запрещены. Да/нет угадывается с вероятностью 50%.
6. **Без перечислений.** «Перечисли 8 хуков жизненного цикла» превращается в серию перекрывающихся cloze: `ngOnChanges → {{c1::ngOnInit}} → ngDoCheck`.
7. **2-3 карточки на idea с разных сторон:** определение, причина, сравнение, применение (у Matuschak это attributes, similarities, causes, significance).
8. **Короткий вопрос.** Длинная формулировка заучивается как картинка, и вспоминание сводится к pattern matching.
9. **Свой пример лучше абстракции.** Карточка с личным примером держится годами: у Wozniak 0 забываний за 5 лет против 20 за год без примера.
10. **Источник и версия** для нестабильных знаний (версии Angular или .NET): секция `Sources` и тег версии, например `angular-19`.
11. **Без длинных цитат** из документации и чата: формулировка должна быть своей.
12. **Мнемоника - только при необходимости.** Для leech и аббревиатур она пишется в `Explanation`, а не в ответе.

## Лимиты

Ни один источник не даёт числовых лимитов. Числа ниже - вывод исследования с обоснованием. Пересматриваются по метрикам (время ответа, доля leech).

| Что | Лимит | Почему |
| --- | --- | --- |
| Вопрос (basic, why, compare, vocab) | ≤25 слов / ≤180 символов | Короткий вопрос не заучивается как картинка (Matuschak) |
| Вопрос `scenario` | ≤60 слов / ≤400 символов | Нужны числа задачи, но читать всё равно в один проход |
| Ответ `basic` / `cloze` / `vocab` | ≤12 слов / ≤80 символов | Minimum information principle |
| Ответ `why` / `compare` | ≤40 слов / ≤280 символов, ≤3 пунктов | Рабочая память вмещает 3-5 chunks (Cowan) |
| Рубрика | ≤5 пунктов, ≤80 слов | Проверить за ~30 с |
| Код в карточке | ≤12 строк, ≤80 символов в строке | Помещается на экран и в рабочую память |
| Cloze | 1 пропуск на вариант, ≤3 варианта на карточку | Wozniak, правило 10 |
| Файл карточки | ≤40 строк / 2 KB (warn), ≤60 строк / 3 KB (error) | SIZE-001. Explanation и Sources помещаются, лекция - нет |
| Время ответа (медиана) | basic ≤10 с, conceptual ≤30 с | Nielsen: ~8 с в среднем. Дольше - значит, карточку надо разбить |
| Новых карточек на тему за захват | 5-20 | Если хороших меньше 5, лучше не добавлять ни одной (Nielsen) |

## Антипаттерны

| Плохо | Почему | Лучше |
| --- | --- | --- |
| «Что такое CQRS?» | Ответ - абзац, и вспомнить его можно наполовину | «[CQRS] Что разделяет CQRS?» → «Модели записи и чтения» |
| «Верно ли, что Redis однопоточный?» | Да/нет, угадывается | «[Redis] Сколько потоков исполняет команды в Redis 7?» |
| «Перечисли принципы SOLID» | Перечисление из 5 элементов | Пять cloze или пять карточек «что нарушено в этом коде?» |
| «Объясни event sourcing» | Нет фокуса, непонятно, что считать ответом | `why`: «[Event sourcing] Почему состояние можно восстановить в любой момент?» |
| «[pl] dom» → «дом» | Нет контекста и примера | «dom» → «дом (м. р.) - *Wracam do domu.*» |

## Как ИИ применяет правила

- Кандидаты проверяются `validate` до показа пользователю. Нарушения лимитов исправляются автоматически, а если не получается - помечаются.
- Для каждой idea ИИ предлагает разные типы: `why`, `compare`, `scenario`, а не три `basic`.
- В тексте кандидата сохраняется язык темы (`lang`). Термины остаются в оригинале.
