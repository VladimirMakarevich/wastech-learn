## Формат

Требования — строки таблицы в секции `## Требования`:

- `ID` — `FR-<область><номер>` или `NFR-<номер>`. ID никогда не переиспользуются, уникальность проверяет TBL-006.
- `Требование` — что должна делать система, одна проверяемая формулировка.
- `Priority` — `MVP` (входит в первый полный цикл), `Later` (после MVP), `Won't` (сознательно не делаем).
- `Status` — `proposed`, `accepted`, `done`, `dropped`.
- `Principles` — какие LP-xx реализует требование (`—`, если ни одного).
- `Journeys` — в каких сценариях J-xx нужно.

## Трассировка

- Каждый принцип LP-xx реализован хотя бы одним FR. Каждый сценарий J-xx покрыт хотя бы одним FR. Обе связи проверяет GRP-003.
- Каждое решение пользователя из интервью отражено в FR, NFR или ADR. Сводка ниже.
