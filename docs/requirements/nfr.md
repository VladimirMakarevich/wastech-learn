# NFR: нефункциональные требования

Свойства системы целиком: качество, производительность, приватность, расширяемость, тестируемость.

## Требования

| ID | Требование | Priority | Status | Проверка |
| --- | --- | --- | --- | --- |
| NFR-01 | Local-first: на десктопе повторение, чтение и поиск работают без интернета; ИИ-функции требуют только чата | MVP | done | Отключить сеть, пройти сессию и найти тему |
| NFR-02 | Без API-ключей в MVP: ни один компонент не вызывает платные API моделей; ИИ работает внутри подписочных чатов | MVP | proposed | Ревью зависимостей и сетевых вызовов |
| NFR-03 | Приватность: контент и журнал хранятся только в приватном git-репозитории и локально; приложение не шлёт данные третьим лицам (без телеметрии и CDN-шрифтов) | MVP | done | Аудит сетевых запросов в DevTools |
| NFR-04 | Детерминизм: один и тот же журнал и одна версия планировщика дают побайтно одинаковое состояние | MVP | done | Тест replay на golden-журнале |
| NFR-05 | Производительность: пересборка кэша на 5k карточек и 50k событий занимает меньше 5 с; следующая карточка появляется меньше чем за 50 мс; bundle golden sample собирается меньше чем за 10 с | MVP | done | Бенчмарк в CI |
| NFR-06 | Расширяемость: новый тип карточки — это схема плюс рендер плюс правила `check`, без миграции журнала; новый хост (CLI, MCP, app, Worker) — без изменения ядра | MVP | proposed | Ревью архитектуры при добавлении типа |
| NFR-07 | Переносимость данных: только Markdown, SVG и JSONL; экспорт в CSV оптимизатора; ни один формат не требует приложения для чтения | MVP | proposed | Открыть репозиторий в VS Code и GitHub |
| NFR-08 | Целостность журнала: только дописывание, никаких перезаписей; дубли отсекаются по `id`; повреждённая строка пропускается с предупреждением и не ломает replay | MVP | proposed | Тесты на дубли и битые строки |
| NFR-09 | Качество контента: перед коммитом в контент-репозитории 0 ошибок mdlint и `check`; в CI то же | MVP | proposed | CI контент-репозитория |
| NFR-10 | i18n: паритет ключей ru, en и pl, плюральные формы CLDR, проверка в CI | MVP | done | Скрипт паритета ключей |
| NFR-11 | Доступность: всё повторение проходится с клавиатуры; контраст WCAG AA; ARIA для кнопок оценки; поддержка `prefers-reduced-motion` | MVP | done | Ручной прогон + axe |
| NFR-12 | Кроссплатформенность: Linux, macOS, Windows; пути через POSIX-нормализацию; `.gitattributes` с `eol=lf` | MVP | proposed | CI на трёх ОС для ядра |
| NFR-13 | Совместимость версий: ts-fsrs, wastech-mdlint, mermaid-cli закреплены точными версиями; версия планировщика пишется в каждое событие; Node ≥24.17 | MVP | proposed | `package.json` + lockfile |
| NFR-14 | Тестируемость: golden content, тесты детерминизма replay, property-тесты очереди (лимиты, siblings, порядок), симуляция бэклога | MVP | done | Набор тестов `srs` и `core` |
| NFR-15 | UI адаптивен от 360 px (узкое окно); хранение событий только через `ReviewStore`; ничего не зависит от Node API в браузере. Сборка под Capacitor вне скоупа ([ADR-0016](../adr/0016-local-only.md)). | MVP | done | e2e на 360 px |
| NFR-16 | Наблюдаемость в локальном режиме: сервер и MCP пишут структурированные логи без контента карточек | Later | proposed | Ревью логов |

## Стратегия тестов

- **Golden content** ([FR-310](fr-content.md)) — общий фикстурный контент-репозиторий для `core`, `srs`, `cli` и `mcp-server`.
- **Replay** — фиксированный журнал на 1000 событий, проверка совпадения снапшота состояния.
- **Property-тесты очереди** (fast-check): при любых журналах лимиты соблюдены, siblings не встречаются в один день, learning steps идут первыми.
- **Симуляция бэклога** — синтетический журнал с перерывом в 14 дней проверяет критерий MVP ([roadmap](../roadmap.md)).
- **Контракт MCP** — интеграционные тесты инструментов на копии golden sample, включая идемпотентность по `requestId`.
