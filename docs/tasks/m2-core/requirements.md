# Требования — M2, ядро

[⌂ index](index.md) · следует из [problem.md](problem.md)

Номера локальные для спеки: `M2-Fnn` — функции, `M2-Nnn` — качества. В скобках — требования проекта из [docs/requirements](../../requirements/README.md), которые они реализуют.

## Функциональные требования

- **M2-F01 — конфигурация** (FR-204). Ядро читает `learn.config.json` и `learn.local.json` и проверяет их схемой. Ошибка называет файл и поле. Без `learn.local.json` имя устройства — hostname.
- **M2-F02 — разбор контента** (FR-307). Темы (`index.md`, `summary.md`, `materials.md`) и карточки разбираются в типизированную модель: front matter проверяется схемой, у карточки вычисляются review items `<id>:<variant>` и `contentHash` секций Question и Answer. Ошибка схемы называет файл и поле.
- **M2-F03 — `check`** (ADR-0012, NFR-09). Команда проверяет правила второго уровня из [mdlint-policy](../../quality/mdlint-policy.md): длину вопроса и ответа по типу, рубрику, код, cloze, `vocab`, уникальность `id`, свежесть SVG, привязку к summary, крупную правку `active`-карточки и расхождение копии пресета mdlint с пресетом CLI. Находки разделены на ошибки и предупреждения. Коды выхода: `0` — чисто, `1` — есть ошибки, `2` — сбой работы.
- **M2-F04 — `build`** (FR-307). Команда собирает content bundle по контракту из [components](../../architecture/components.md): JSON с метаданными доменов, тем и карточек и пререндеренный HTML (GFM, Shiki в светлой и тёмной теме, KaTeX, встроенные SVG), прошедший `rehype-sanitize`. При ошибке схемы bundle не пишется.
- **M2-F05 — `render`**. Команда рендерит `content/**/diagrams/*.mmd` в SVG с маркером `source-sha256`; режим `--check` только сообщает об устаревших. Заменяет временный скрипт контент-репозитория.
- **M2-F06 — журнал**. Ядро читает все `reviews/**/*.jsonl`, проверяет каждое событие схемой v1 из [review-log](../../content/review-log.md), отбрасывает дубли по `id`, упорядочивает по `ts`, затем по `id`, применяет `undo`. Битая строка — находка с файлом и номером строки, а не молчаливый пропуск. `content-fs` умеет атомарно дописать событие в файл своего writer.
- **M2-F07 — replay** (FR-204, FR-211). `srs` прогоняет события каждого review item через `ts-fsrs@6.0.1` с параметрами из конфигурации и выдаёт состояние на момент `now`: stability, difficulty, R, due, reps, lapses, фазу (new, learning, review, relearning), suspend и признак leech после `leechThreshold` lapses. Учитываются `review`, `reset`, `suspend`, `unsuspend`, `manual_due`; `practice` расписание не меняет.
- **M2-F08 — очередь дня** (FR-201, FR-206, FR-207, FR-208). На момент `now` с границей дня `dayStartsAt` в `timezone`: сначала learning и relearning с подошедшим шагом, затем due review items из всех доменов вперемешку, затем новые в пределах лимитов домена. Siblings (варианты одной карточки и карточки одной `idea`) не попадают в один день. Работает политика бэклога из [backlog](../../scheduling/backlog.md): дневной лимит, порядок при бэклоге, пауза и плавный возврат новых, leech скрыты. Очередь отдаёт оценку времени в минутах и умеет режим «N минут» без новых карточек.
- **M2-F09 — `simulate`** (FR-208). Команда строит синтетический журнал с перерывом заданной длины и проигрывает сессии по 15 минут. Отчёт: сколько дней разбирается бэклог, нагрузка по дням, когда вернулись новые. Сравнивает порядки очереди при бэклоге, чтобы закрыть Q-01.

## Нефункциональные требования

- **M2-N01 — детерминизм** (NFR-04). Один журнал и одна версия планировщика дают побайтно одинаковый снимок состояния, в том числе при перемешанном порядке файлов и строк. Часы, случайность и часовой пояс — только входные параметры.
- **M2-N02 — производительность** (NFR-05). Replay 50k событий по 5k карточкам — меньше 5 с; выбор следующей карточки из готовой очереди — меньше 50 мс; `build` golden sample — меньше 10 с.
- **M2-N03 — тестируемость** (NFR-14). Golden content, тест replay на журнале около 1000 событий, property-тесты очереди, симуляция бэклога — как в [.rules/testing.md](../../../.rules/testing.md).
- **M2-N04 — переносимость.** `core` и `srs` работают в браузере: без Node API, файловой системы и сети, не зависят друг от друга.
- **M2-N05 — совместимость.** Ядро читает события `v: 1` и не падает на незнакомых необязательных полях. Существующий golden sample проходит `check` и `build` без правок, кроме найденных настоящих ошибок.
- **M2-N06 — приватность.** Ни сети, ни вызовов моделей, ни телеметрии. Сообщения CLI содержат пути, правила и счётчики, а не текст карточек.

## Данные и хранение

- **Новых форматов в git нет.** Журнал v1 и `learn.config.json` уже описаны, M2 впервые читает и пишет их кодом.
- **Content bundle** — производный файл, в git контента не коммитится.
- **Кэш** в `.cache/` (уже в `.gitignore` контента) удаляется и пересобирается без потерь.

## Зависимости и допущения

- `ts-fsrs@6.0.1` с FSRS-7 и параметрами из [srs](../../scheduling/srs.md); точные версии всех зависимостей.
- Стек конвейера Markdown — unified, remark, rehype, Shiki, KaTeX, `rehype-sanitize`; схемы — Zod.
- `@mermaid-js/mermaid-cli` для `render` (тянет Chromium, R-06).
- Копия golden sample в `fixtures/golden/` фреймворка; Vitest и fast-check ставятся с первым пакетом.
