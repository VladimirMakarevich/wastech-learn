# План реализации — M3, захват

[⌂ спека](../index.md) · строит [design.md](../design.md) к [acceptance-criteria.md](../acceptance-criteria.md)

## Стратегия

Код M3 начинается после фаз 01–08 M2 (схемы, разбор, `check`, CLI, журнал, replay, очередь); `render` нужен только к фазе 06. Сначала формы и чистые функции в `core` (01–03), затем безопасный путь записи в `content-fs` (04), затем сервер по группам инструментов (05–07), hook и skills (08–09). Публикация и подключение контента (10) — внешний шаг с согласия владельца, приёмка на реальных темах (11) — последней. Критический путь — путь записи: на нём держатся идемпотентность, атомарность и проверка до записи.

## Общее для всех фаз

- **Коммиты:** Conventional Commits (`feat(mcp-server): …`, `feat(core): …`), только после «да» владельца, без строк об агенте; изменения в контенте — отдельным коммитом там.
- **Тесты:** контракт на каждый инструмент; временные копии golden, никогда не настоящий контент.
- **Документы:** фаза, которая меняет поведение инструмента, обновляет [mcp-tools](../../../ai/mcp-tools.md) в том же коммите; фаза 11 сводит остальное.
- **DoD:** [definition-of-done.md](../definition-of-done.md).

## Передача в реализацию

Фазы выполняет skill `implement` по одной: `assess-refactor` перед кодом, статус в этой таблице, `/code-review` через subagents после фазы.

## Риски

| Риск | Вероятность | Митигация |
| --- | --- | --- |
| API MCP SDK меняется между версиями | средняя | Точная версия; контрактные тесты через клиент того же SDK |
| `lintContent` mdlint не видит наложенные файлы так же, как `lint` | средняя | Проверка с наложением тестируется на golden против `wastech-mdlint lint` |
| Лимиты подписки при захвате (R-04) | высокая | Короткие ответы (AC-N03), `dryRun` вместо повторной записи, квиз батчами |
| ИИ генерирует слабые карточки (R-09) | высокая | Отбор человеком, `check` до записи, поиск дублей; skill требует 8–15 кандидатов и не пишет без отбора |
