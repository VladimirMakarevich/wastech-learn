# Требования - M3, захват

[⌂ index](index.md) · следует из [problem.md](problem.md)

Номера локальные для спеки: `M3-Fnn` - функции, `M3-Nnn` - качества. В скобках - требования проекта из [docs/requirements](../../requirements/README.md). Инструменты подробно описаны в [mcp-tools](../../ai/mcp-tools.md), формат пакета - в [learning-package](../../ai/learning-package.md).

## Функциональные требования

- **M3-F01 - сервер** (FR-107). Stdio MCP-сервер `wastech-learn-mcp` работает с одним репозиторием из `--content`, регистрирует инструменты контента и квиза, ошибки отдаёт как `{ code, message, hint }`.
- **M3-F02 - инструменты контента** (FR-102, FR-104, FR-105, FR-107, FR-115). `create_topic` (с `familiarity`, `keyIdea`, `pretest[]`), `add_cards` (новые `id`, файлы `cards/<id>.md`, обновление `## Cards` в `index.md`, статус `active` или `draft`), `update_card` (при `meaningChanged` старая карточка уходит в `retired`, создаётся новая), `save_summary`, `save_materials`.
- **M3-F03 - проверка до записи** (FR-108). Каждая запись проходит mdlint из `@wastech-mdlint/core` по корпусу с наложенными файлами (`lintContext`) и `check`; при ошибках ничего не пишется, находки возвращаются ИИ. `validate` проверяет пути или черновик без записи.
- **M3-F04 - идемпотентность и сухой прогон** (FR-116). Мутирующие инструменты принимают `requestId`: повтор возвращает прежний результат и ничего не пишет. `dryRun` даёт находки и будущие пути без записи.
- **M3-F05 - `save_diagram`** (FR-111). Принимает Mermaid и `alt`, проверяет синтаксис и наличие `alt`, пишет `.mmd` и SVG с маркером `source-sha256` через `render` из M2.
- **M3-F06 - `search`** (FR-103, [ADR-0014](../../adr/0014-search-minisearch.md)). Поиск MiniSearch по темам и карточкам с фильтрами по домену, типу и статусу; тот же индекс потом попадёт в bundle для UI. Используется для поиска дублей перед кандидатами.
- **M3-F07 - learning package** (FR-110). `import_package` разбирает пакет v1 из `inbox/` схемой `core` и возвращает тему и кандидатов; запись идёт инструментами контента; после импорта пакет оказывается в `inbox/done/`. Промпт экспорта есть на en, ru и pl.
- **M3-F08 - квиз** (FR-117, FR-205, FR-210, FR-211). `queue_status`, `quiz_next` (≤10, без ответа), `reveal`, `record_review` (событие в `reviews/<device>/mcp-YYYY-MM.jsonl` с `aiSuggested`, `grader`, `confidence`, `durMs`; в ответе следующий due), `undo_last` (событие `undo`). Когда `lapses` достигают порога, `record_review` пишет `suspend`.
- **M3-F09 - skills** (FR-101, FR-104…FR-106, FR-110, FR-210). `learn-capture`, `learn-import`, `learn-quiz` в `skills/` фреймворка по конвенциям `wastech-skills` и [capture](../../ai/capture.md): триггеры, шаги, «Done when», «What not to do», шаблоны. Захват заканчивается мини-квизом из 3 новых карточек.
- **M3-F10 - hook** (FR-109). `PostToolUse` на `Write|Edit` по `content/**` в контент-репозитории запускает mdlint и `check` по изменённому файлу и возвращает находки агенту.
- **M3-F11 - `new-id`.** Генератор `id` (8 символов Crockford base32, внешний RNG) в `core`; сервер проверяет уникальность; команда CLI `new-id` для ручной работы.
- **M3-F12 - подключение контента.** В `wastech-learn-content` появляются `.mcp.json` с сервером, `.claude/settings.json` с hook и skills с фиксацией в `skills-lock.json`; сначала на локальной сборке фреймворка.

## Нефункциональные требования

- **M3-N01 - приватность** (NFR-02, NFR-03). Без сети и вызовов моделей; транспорт только stdio; инструменты не выполняют пользовательский код и не открывают URL.
- **M3-N02 - безопасность путей.** Любой путь вне `--content` отклоняется, включая `..` и символические ссылки наружу.
- **M3-N03 - экономия лимита** (R-04). Ответы короткие: пути, `id`, находки, а не тексты файлов; исключения - `reveal` и `import_package`.
- **M3-N04 - надёжность записи.** Файл пишется атомарно (временный файл и переименование); прерванная запись не оставляет половину файла; группа файлов одного вызова либо пишется вся, либо не пишется.
- **M3-N05 - тестируемость** (NFR-14). Контрактный тест на каждый инструмент на временной копии golden: валидация, идемпотентность, ограничение путей, `quiz_next` без ответа.
- **M3-N06 - время захвата.** Захват реальной темы до файлов и мини-квиза - ≤15 минут без учёта диалога; проверяется вручную при приёмке.
- **M3-N07 - язык.** Находки идут из каталога сообщений `core` на `uiLanguage`; skills говорят на языке пользователя, артефакты пишут на `lang` темы.

## Данные и хранение

- **Новых форматов в git нет.** Карточки, темы, summary и журнал пишутся по существующим описаниям; события MCP - в файл writer `mcp`.
- **Схема learning package v1** впервые описывается кодом в `core`.
- **`inbox/done/`** - архив импортированных пакетов, коммитится.
- **Результаты по `requestId`** хранятся в `.cache/`: потеря кэша ослабляет только защиту от повтора, не данные.

## Зависимости и допущения

- Готовы фазы M2: схемы, разбор, `check`, журнал, replay, очередь, `render`.
- До публикации `@wastech-learn/*` в npm контент подключается к локальной сборке через `file:`-ссылки; публикация - отдельным решением после локальной приёмки (M3-Q9).
- `@modelcontextprotocol/sdk`, MiniSearch, `@wastech-mdlint/core` 0.4.1 с точными версиями.
