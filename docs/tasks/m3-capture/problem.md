# Проблема - M3, захват

[⌂ index](index.md)

## Проблема, как она поставлена

Знание рождается в разговоре с ИИ, но оседает только там. Через неделю от разбора остаётся ощущение «я это знаю», а писать карточки вручную долго, поэтому их не пишут ([vision](../../product/vision.md)). Веха M3 из [roadmap](../../roadmap.md) - превратить разговор в файлы темы и повторение прямо в чате: MCP-сервер `wastech-learn-mcp`, skills `learn-capture`, `learn-import`, `learn-quiz`, hook в контент-репозитории и промпт learning package. Готово, когда одна реальная тема захвачена из Claude Code и одна импортирована из ChatGPT.

## У кого эта проблема

- **Автор** - единственный пользователь. Разбирает темы в Claude Code и иногда в ChatGPT, правит контент в VS Code, повторяет нерегулярно ([journeys](../../product/journeys.md): J-01, J-02, J-09).
- **ИИ в чате** как исполнитель: ему нужны инструменты, которые валидируют запись и не раскрывают ответ раньше попытки.

## Текущая ситуация

- После M2 контент можно проверить и собрать, но создать его можно только руками: тема, карточки с `id`, summary по шаблону, диаграмма с маркером хэша.
- Из ChatGPT выйти нечем: формат learning package описан ([learning-package](../../ai/learning-package.md)), но ничто его не разбирает.
- Повторять можно только после M4: журнал после M2 читается, но писать в него оценки некому.
- В контент-репозитории подключён только MCP mdlint; нет hook, skills и `skills-lock.json`.

## Почему сейчас

- Следующая веха после M2; M4 без контента и журнала нечего показывать, а обкатке M5 нужно ≥5 тем из Claude Code и ≥1 из ChatGPT.
- Ядро M2 даёт всё, на что опирается захват: схемы, `check`, дозапись в журнал, replay, очередь, `render`.
- Захват - главный источник контента. Чем раньше он работает, тем раньше копится реальный журнал для настройки лимитов и порядка очереди.

## Сигналы и факты

- Критерии MVP из [fr-capture](../../requirements/fr-capture.md): захват темы ≤15 минут без учёта диалога; результат - summary, материалы, ≥1 диаграмма, 5-12 карточек; импорт без ручной правки файлов, кроме отбора карточек; после захвата `lint` и `check` дают 0 ошибок.
- Риски из [risks-and-questions](../../risks-and-questions.md): лимиты подписки (R-04), MCP в ChatGPT не на всех тарифах (R-05), ИИ генерирует много слабых карточек (R-09), тяжёлая установка mermaid-cli (R-06).
- Эксперимент Bastani et al. (2025): ИИ, который выдаёт ответы, ухудшил экзамен на 17%, тьютор с подсказками - нет ([tutor-and-grading](../../ai/tutor-and-grading.md)).

## Ограничения, заданные заранее

- Только подписки: без API-ключей и вызовов моделей из кода ([ADR-0008](../../adr/0008-capture-via-subscription-chats.md)).
- ИИ предлагает, человек решает: отбор карточек и финальная оценка - за пользователем ([ADR-0009](../../adr/0009-ai-suggests-user-confirms.md)).
- MCP-сервер - тонкий хост; мутирующие инструменты идемпотентны по `requestId`, есть `dryRun`, пути ограничены `--content`, `quiz_next` не отдаёт ответ ([.rules/architecture.md](../../../.rules/architecture.md)).
- Каждая запись проходит mdlint и `check` до записи ([ADR-0012](../../adr/0012-two-tier-validation.md)).
- Транспорт MVP - stdio для Claude Code; remote MCP - фаза 2.
