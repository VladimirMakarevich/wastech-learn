# Требования - приложение: правка тем и карточек в браузере

[⌂ index](index.md) · следует из [problem.md](problem.md)

Номера локальные для спеки: `AE-Fnn` - функции, `AE-Nnn` - качества. В скобках - требования проекта из [docs/requirements](../../requirements/README.md). Экраны - в [screens](../../ux/screens.md), вид - в [DESIGN.md](../../../DESIGN.md).

## Функциональные требования

### Где начинается правка

- **AE-F01 - карточка в Cards.** В боковой панели карточки есть кнопка с карандашом «Править» (клавиша `e`). Она открывает текст файла карточки в редакторе на месте содержимого панели.
- **AE-F02 - тема на Topic.** Карандаш в шапке темы открывает редактор файлов темы: `summary.md` по умолчанию, `index.md` и `materials.md` - переключением. Карандаш у блока «Материалы» сразу открывает `materials.md`.
- **AE-F03 - с того места, где читаешь.** Редактор summary открывается с курсором на секции, которая сейчас на экране.
- **AE-F04 - карточка на Review** (FR-215). После показа ответа карточку можно открыть в редакторе. Сессия не прерывается: после сохранения или отмены карточка показана заново с ответом, и её можно оценить. Оценка записывается для того текста, что на экране.
- **AE-F05 - VS Code остаётся.** «Открыть в VS Code» доступно там же, где сейчас, но клавиша `e` теперь открывает правку в приложении, а VS Code - `Shift+E` (FR-312).

### Редактор

- **AE-F06 - обычный текст.** Редактор показывает весь файл как Markdown-текст, включая front matter, моноширинным шрифтом. «Сохранить» - кнопкой и `Ctrl/Cmd+S`, «Отмена» - кнопкой и `Esc`.
- **AE-F07 - несохранённое не теряется молча.** Если текст изменён, закрытие редактора, переход на другой экран и закрытие вкладки сначала спрашивают подтверждение.

### Сохранение

- **AE-F08 - проверка до записи** (ADR-0012). Перед записью правка проходит оба уровня проверки (mdlint и `check`) по всему репозиторию с этой правкой. Если есть ошибки, ничего не записывается: текст остаётся в редакторе, рядом - список находок со строкой и сообщением на языке интерфейса; выбор находки ставит курсор на её строку.
- **AE-F09 - предупреждения не мешают.** Правка с одними предупреждениями записывается, предупреждения показываются после записи.
- **AE-F10 - `id` неизменен.** Правка, которая меняет `id` карточки, не записывается; приложение объясняет, что на `id` держится история повторений.
- **AE-F11 - смысл изменился?** Если проверка видит крупную правку active-карточки, до записи пользователь выбирает одно из двух: «та же карточка» (`id` и история сохраняются) или «новая карточка» (эта уходит в `retired`, текст записывается в новую карточку с новым `id` и попадает в `## Cards` темы). Так же, как `update_card` с `meaningChanged`.
- **AE-F12 - заголовок в списке темы.** Если изменился заголовок карточки (`#`), список `## Cards` в `index.md` темы показывает новый заголовок; оба файла меняются одной записью.
- **AE-F13 - дата обновления.** Запись `summary.md` и `materials.md` ставит в `updated` сегодняшнюю дату в зоне из `learn.config.json`, как инструменты MCP, если пользователь не поменял её сам.
- **AE-F14 - правка снаружи не затирается.** Если файл изменили после открытия редактора (VS Code, агент, другая вкладка), запись отказывается. Текст в редакторе остаётся; приложение говорит, что файл изменился, и даёт загрузить свежую версию - с подтверждением, потому что черновик при этом заменяется.
- **AE-F15 - после записи.** Редактор закрывается, экран показывает новый текст из пересобранного bundle, появляется короткое «Сохранено». Повторное сохранение того же текста ничего не меняет и не считается ошибкой.

### Язык

- **AE-F16 - тексты.** Все новые подписи, сообщения, находки `check` и подтверждения - на ru, en и pl, спокойные и без вины (не «вы сломали файл», а «в строке 12 не хватает секции Answer»). Находки mdlint показываются его английским сообщением с номером правила: каталога ru и pl у mdlint нет.

## Нефункциональные требования

- **AE-N01 (безопасность)** (NFR-03). Сервер по-прежнему только на `127.0.0.1` и принимает изменения только со своей страницы (Host, Origin, JSON). Читать исходник и писать можно только файлы карточек и `index.md`, `summary.md`, `materials.md` тем, которые есть в bundle; пути проверяются внутри репозитория, включая символические ссылки. Размер тела ограничен. Текст правки не попадает в логи; на экран правленый текст приходит только через компилятор и санитайзер bundle.
- **AE-N02 (целостность).** Запись атомарна: все файлы одной правки (карточка и `index.md`, старая и новая карточка) меняются вместе или не меняются вовсе. Две записи не идут одновременно, в том числе из двух вкладок. Журнал повторений не меняется.
- **AE-N03 (скорость)** (NFR-05). Редактор открывается быстрее 300 мс. Проверка и запись на реальном контент-репозитории - быстрее 2 с; новый текст виден на экране не позже чем через 2 с после записи.
- **AE-N04 (доступность).** Всё доступно с клавиатуры. При открытии фокус в редакторе, после закрытия - на кнопке, которая его открыла. Подтверждения - модальные диалоги с ловушкой фокуса. axe без нарушений `serious` и `critical` в обеих темах; редактор работает при ширине 360 px (NFR-15).
- **AE-N05 (тесты).** Логика записи проверяется на временной копии golden-контента; маршруты сервера - через `app.request()`; e2e - Playwright на `serve` над golden-копией, без сети.
- **AE-N06 (вес приложения).** Начальный бандл приложения остаётся в бюджете сборки (`angular.json`).

## Данные и хранение

- Новых форматов нет. Меняются только файлы карточек и `index.md`, `summary.md`, `materials.md` тем. При «новой карточке» (AE-F11) появляется файл с новым `id`, у старой `status` становится `retired`.
- Журнал повторений не меняется. Изменённая карточка с тем же `id` получает новый `contentHash`, и Review уже помечает её как изменённую после прошлого повторения (FR-218).
- Сервер приложения впервые пишет в Markdown - это расширение границы [ADR-0007](../../adr/0007-local-server-phase-1.md). Новый ADR общий со спекой [app-sync-and-cards](../app-sync-and-cards/index.md) (AS-F14): его пишет та задача, что пойдёт в работу первой.

## Зависимости и допущения

- Переиспользуются путь записи с проверкой из M3 (`applyWrite`, логика преемника в `updateCard`) и наблюдение за файлами из M4 (watcher, SSE).
- В контент-репозитории есть `wastech-mdlint.config.json`: без него первый уровень проверки не работает.
- Коммит и отправка правки - в [app-sync-and-cards](../app-sync-and-cards/index.md). Без неё правка остаётся незакоммиченной, как после VS Code.
