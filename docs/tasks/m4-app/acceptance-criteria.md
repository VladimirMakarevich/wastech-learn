# Критерии приёмки — M4, приложение

[⌂ index](index.md) · требования — [requirements.md](requirements.md) · дизайн — [design.md](design.md)

«Копия» — временная копия golden sample; «журнал-фикстура» — сгенерированный журнал на копии, где к показу ≥20 review items. «Контракт» — маршрут через `app.request()` без сокетов; «e2e» — Playwright (Chromium) на `wastech-learn serve` над копией, время браузера через `page.clock`.

## Функции

| # | Дано → когда → тогда | Проверка |
| --- | --- | --- |
| AC-F01 | `serve --content <копия>` → слушает только `127.0.0.1`, `/` и глубокие ссылки вроде `/topic/…` отдают приложение; занятый порт → ошибка с подсказкой про `--port` | CLI-тест + контракт |
| AC-F02a | `POST /api/events` с событием `writer: web` своего устройства → строка в `reviews/<device>/web-YYYY-MM.jsonl`; повтор того же `id` → `duplicates: 1`, второй строки нет | контракт |
| AC-F02b | Событие с `writer: mcp`, чужим `device` или нарушением схемы → `400`, файл не изменился | контракт |
| AC-F03a | Правка вопроса карточки в копии → `content-changed`, новый `GET /api/bundle` отдаёт новый `questionHtml` | unit `watchRepository` + контракт |
| AC-F03b | Файл с ошибкой схемы → `build-failed` с файлом и строкой, `GET /api/bundle` отдаёт прежний bundle; в приложении баннер | контракт + e2e |
| AC-F03c | Своя дозапись не порождает `events-changed`; строка в файле другого устройства — порождает | unit `watchRepository` |
| AC-F04 | `HttpReviewStore`: при недоступном сервере событие остаётся в очереди и `localStorage`, после восстановления досылается один раз; `app` не импортирует `content-fs` | unit с подменой `fetch` + lint |
| AC-F05 | Bundle копии содержит `searchIndex`; поиск слова из вопроса даёт эту карточку первой; польское слово находится без диакритики; при поиске нет сетевых запросов | unit + e2e |
| AC-F06 | Вопрос → `Space` → ответ и 4 кнопки, интервалы под ними равны `session.preview`; оценка пишет `review` с `durMs`, `contentHash`, `sched`; порядок карточек равен очереди `srs` | unit движка + e2e |
| AC-F07 | `2` до показа ответа → `confidence: 2` в событии; без выбора → `null` | unit + e2e |
| AC-F08 | «5 минут» на журнале-фикстуре: новых карточек нет, сессия останавливается по оценке времени, текущая карточка дорешивается; «Вся очередь» проходит всю очередь дня | unit движка |
| AC-F09 | `u` после оценки → `undo` на последнее событие, карточка снова в очереди; `u` после оценки с автоматическим `suspend` → два `undo` | unit + e2e |
| AC-F10 | `scenario`: отмеченные пункты рубрики дают оценку по правилам [tutor-and-grading](../../ai/tutor-and-grading.md), выбор за пользователем; `vocab` показывает `fwd` и `rev`; `cloze` скрывает только пропуск показываемого варианта | unit + e2e |
| AC-F11 | `o` открывает тему; `e` даёт ссылку `vscode://file/<абсолютный путь>`; `!` пишет `suspend`, карточка уходит из очереди, `unsuspend` из Browser возвращает её; оценка, после которой `lapses` = порог, пишет `suspend`; при новом `contentHash` значок «изменена», `reset` пишет событие; `b` прячет карточку до конца сессии без события | unit + e2e |
| AC-F12 | Сессия из 20 review items на журнале-фикстуре проходится только `keyboard.press`, без мыши; `Esc` показывает итоги; фокус виден на каждом шаге | e2e |
| AC-F13 | Home: «N ≈ M мин» и новые по доменам совпадают с очередью `srs`, прогноз на 7 дней; через 14 дней без событий — план возврата без слов о пропусках | unit `srs/metrics` + e2e |
| AC-F14 | Итоги: число, минуты, true retention сессии, ошибки при уверенности 3 со ссылками на карточки, прогноз на завтра; ни одной строки о стриках | e2e |
| AC-F15 | Тема golden: все 12 секций в оглавлении, SVG-схема, код Shiki, KaTeX; `Self-check` раскрывается по одному вопросу | e2e |
| AC-F16 | Browser: фильтр `leech` на журнале-фикстуре показывает только leech; фильтры домена, темы, тега, типа, статуса и «изменена» сужают список; колонки R, due, lapses, последняя оценка | e2e |
| AC-F17 | Stats: true retention young и mature за 7 и 30 дней и прогноз на 30 дней совпадают с ручным подсчётом на golden-журнале | unit `srs/metrics` + e2e |
| AC-F18 | Settings показывает DR, лимиты и устройство из `/api/status`; язык, тема и длительность переживают перезагрузку; в копии после работы с настройками `git status` чистый | e2e |
| AC-F19 | Смена языка ru → en → pl без перезагрузки меняет все подписи; паритет ключей и аудит литералов проходят; плюралы 1, 2, 5 верны на трёх языках | unit + e2e |
| AC-F20 | С подменённым голосом `pl-PL` у польской карточки есть 🔊, `p` вызывает `speak` с `lang: pl-PL`; без голоса кнопки нет и ошибок в консоли нет | e2e с подменой `speechSynthesis` |

## Качества

| # | Дано → когда → тогда | Проверка |
| --- | --- | --- |
| AC-N01 | За полный обход всех экранов ни одного запроса не к `127.0.0.1`; логи сервера без текста карточек | e2e + ревью |
| AC-N02 | Медиана времени от оценки до показа следующей карточки на 20 карточках < 50 мс; правка файла видна < 2 с; replay синтетических 50k событий на 5k карточек в Chromium < 5 с | e2e |
| AC-N03 | Инкрементальный replay движка равен полному (property-тест); после e2e-сессии due каждого оценённого item из replay записанного журнала в Node совпадает с due в Browser | unit + e2e |
| AC-N04 | axe: 0 нарушений `serious` и `critical` на каждом экране в обеих темах; у кнопок оценок `aria-keyshortcuts` и полная подпись; `prefers-reduced-motion` отключает анимацию | e2e |
| AC-N05 | На ширине 360 px нет горизонтальной прокрутки ни на одном экране; экраны в тёмной и светлой темах соответствуют DESIGN.md | e2e + ревью дизайна |
| AC-N06 | Словари ru, en, pl не содержат запрещённых формулировок из [interaction](../../ux/interaction.md) | unit + ревью |
| AC-N07 | У каждого маршрута сервера есть контрактный тест | ревью |
| AC-N08 | Чужой `Host` или `Origin` → `403`; `POST` не JSON → `415`; тело больше 256 KB → `413`; заголовка `Access-Control-Allow-Origin` нет | контракт |
| AC-N09 | После переноса логики в `session` тесты `content-fs` и `mcp-server` проходят без изменения ожиданий | `npm test` |
| AC-N10 | На реальном `wastech-learn-content` сессия из 20 review items пройдена только с клавиатуры, оценки в журнале, `check` — 0 ошибок | вручную, запись в журнал изменений спеки |
