## Функциональные требования

### Сервер и данные

- **M4-F01 - локальный сервер** (FR-312, [ADR-0007](../../adr/0007-local-server-phase-1.md)). `wastech-learn serve --content <path>` одной командой поднимает сервер на `127.0.0.1`, отдаёт собранное приложение, content bundle и журнал и открывает браузер.
- **M4-F02 - запись событий.** Сервер принимает события, проверяет каждое схемой `core`, дописывает только в `reviews/<device>/web-YYYY-MM.jsonl` своего устройства и отбрасывает повтор по `event.id`. Устройство берётся из `learn.local.json`.
- **M4-F03 - живые изменения** (FR-311, FR-312). Сервер следит за `content/**`, `reviews/**` и `learn.config.json`, пересобирает bundle и сообщает приложению; правка карточки в VS Code или `git pull` видны без перезапуска. Ошибка сборки показывается в приложении с файлом, а последний рабочий bundle остаётся.
- **M4-F04 - `ReviewStore`** ([components](../../architecture/components.md)). Приложение читает и пишет журнал только через `ReviewStore`; реализация фазы 1 - HTTP к локальному серверу. Replay, очередь и метрики считаются в клиенте пакетом `srs`.
- **M4-F05 - поиск в bundle** (FR-304, [ADR-0014](../../adr/0014-search-minisearch.md)). Bundle несёт сериализованный индекс MiniSearch из `core/search`; поиск по темам и карточкам работает в браузере без запросов к серверу.

### Повторение

- **M4-F06 - сессия** (FR-201, FR-202, FR-206, FR-208). Очередь дня из `srs`: вопрос → попытка → «Показать ответ» → ответ, объяснение и схема → 4 оценки с подписями и прогнозом интервала; оценка пишет событие `review` с `durMs`, `contentHash` и `sched`.
- **M4-F07 - уверенность** (FR-203). До показа ответа можно отметить уверенность 1-3 или пропустить; значение попадает в событие.
- **M4-F08 - режимы сессии** (FR-207, FR-401). «5 минут» (длительность 5, 10 или 15 из настроек) - без новых карточек, по оценке времени, текущая карточка дорешивается; «Вся очередь» - до конца очереди дня.
- **M4-F09 - отмена** (FR-205). `u` или `Ctrl+Z` пишет `undo` на последнюю оценку сессии и возвращает review item в очередь.
- **M4-F10 - типы карточек** (FR-209, FR-502, FR-503). `basic`, `why`, `compare` - ответ целиком; `scenario` - рубрика-чеклист, оценка предлагается по отмеченным обязательным пунктам, решает пользователь; `vocab` - варианты `fwd` и `rev`; `cloze` и `grammar-cloze` скрывают пропуск показываемого варианта.
- **M4-F11 - действия над карточкой** (FR-211, FR-214, FR-215, FR-218). Открыть тему (`o`), открыть файл в VS Code (`e`), отложить (`!`, событие `suspend`) и вернуть из браузера карточек (`unsuspend`). При достижении порога lapses пишется `suspend`, как в квизе MCP. Карточка с изменившимся `contentHash` помечается, её можно сбросить (`reset`). `b` скрывает карточку до конца сессии без события (M4-Q2).
- **M4-F12 - клавиатура** (NFR-11). Вся сессия проходится с клавиатуры по таблице [interaction](../../ux/interaction.md); `Esc` завершает сессию и показывает итоги; фокус всегда виден.

### Экраны

- **M4-F13 - Home** (FR-401, FR-505). «N карточек ≈ M мин», новые по доменам, прогноз на 7 дней, три кнопки сессии, список доменов и тем с числом карточек и due (FR-301). После паузы больше 3 дней - спокойный план возврата вместо долга.
- **M4-F14 - Session end** (FR-402). Сколько повторено и за сколько минут, true retention сессии, ошибки при уверенности «точно» со ссылкой на эти карточки, прогноз на завтра; кнопки «На главную» и «Ещё 5 минут». Без стриков.
- **M4-F15 - Topic** (FR-302, FR-303, FR-309). Оглавление секций summary, текст с таблицами, кодом Shiki, KaTeX и SVG-схемами, материалы и карточки темы со статусом, R и due; `Self-check` раскрывается по одному вопросу; «Открыть в VS Code».
- **M4-F16 - Browser** (FR-304, FR-305). Поиск и фильтры по домену, теме, тегу, типу, статусу, `leech` и «изменена»; таблица с R, due, lapses и последней оценкой; просмотр карточки в боковой панели.
- **M4-F17 - Stats** (FR-403). True retention young и mature за 7 и 30 дней и прогноз нагрузки на 30 дней - из журнала функциями `srs`.
- **M4-F18 - Settings** (FR-509, FR-504). Язык UI, тема (как в ОС, тёмная, светлая), длительность «5 минут», проверка голоса `pl-PL`; показ DR, лимитов по доменам и имени устройства; правка - в `learn.config.json` через VS Code ([M4-Q1](questions.md)).

### Язык

- **M4-F19 - i18n** (FR-501, FR-509, NFR-10). UI на ru, en и pl с плюралами CLDR, даты и числа через `Intl`; язык переключается без перезагрузки; заголовки секций контента переводятся при показе, текст контента - на `lang` темы. Механизм и проверка паритета ключей перенесены из `wastechlab-mobile-template`.
- **M4-F20 - озвучка** (FR-504). Для `pl` кнопка 🔊 и клавиша `p` озвучивают через Web Speech API; без голоса `pl-PL` кнопки нет и ошибок нет.

## Нефункциональные требования

- **M4-N01 - local-first и приватность** (NFR-01, NFR-03). Повторение, чтение и поиск работают без интернета; ни одного запроса за пределы `127.0.0.1`; шрифты и скрипты локальные; логи без текста карточек.
- **M4-N02 - производительность** (NFR-05). Следующая карточка появляется меньше чем за 50 мс; правка в VS Code видна меньше чем через 2 с; replay 50k событий на 5k карточек в браузере меньше 5 с.
- **M4-N03 - детерминизм** (NFR-04). Состояние в клиенте после сессии побайтно совпадает с replay того же журнала в Node.
- **M4-N04 - доступность** (NFR-11). Контраст WCAG AA, `aria-keyshortcuts` и полные подписи у оценок, цвет не единственный признак, `prefers-reduced-motion`; проверка axe на ключевых экранах.
- **M4-N05 - вид** (NFR-15, [ADR-0006](../../adr/0006-headless-core-angular-ui.md)). Evening Glass по DESIGN.md в тёмной и светлой темах, схемы читаются в обеих (Q-10); раскладка десктопная, без горизонтальной прокрутки от 360 px.
- **M4-N06 - тон** ([interaction](../../ux/interaction.md)). Все тексты без вины, стриков и «пропущенных дней».
- **M4-N07 - тестируемость** (NFR-14). Контрактный тест на каждый маршрут сервера на копии golden; юнит-тесты новой логики в `srs` и `core`; UI-тесты ключевого сценария выбранным в M4 инструментом.
- **M4-N08 - безопасность сервера** ([security](../../../.rules/security.md)). Только `127.0.0.1`, без wildcard CORS, ограничение размера тела, HTML только из bundle.

## Данные и хранение

- **Новых форматов в git нет.** События приложения - существующая схема v1 в файле writer `web`.
- **Bundle** получает поле `searchIndex`; версия bundle остаётся 1, поле необязательное.
- **Настройки интерфейса** (язык, тема, длительность) - локальные для устройства и в git не попадают.

## Зависимости и допущения

- Готовы M2 и M3: схемы, bundle, replay, очередь, бэклог, поиск, запись журнала, правило leech в квизе.
- Логику, которая нужна и квизу MCP, и приложению (сборка события оценки, порог leech, прогноз интервала), выносим из `content-fs` в `srs` или `core`, иначе браузер её не получит.
- Angular, Hono и инструмент UI-тестов добавляются точными версиями после проверки лицензии и зависимостей.
