# Фаза 13 — Качество

[⌂ plan](index.md) · [спека](../index.md)

- **Статус:** ☐
- **Зависит от:** 09–12
- **Даёт:** Доступность, 360 px, сеть, замеры, ревью дизайна

## Цель

Проверить приложение целиком по качествам M4-N01…N06 и снять замеры, которые решают, нужна ли инкрементальная сборка.

## Шаги

1. axe (`@axe-core/playwright`) на каждом экране в тёмной и светлой темах; `prefers-reduced-motion`.
2. Ширина 360 px: без горизонтальной прокрутки на всех экранах.
3. Полный обход экранов с аудитом сети; ревью логов сервера на отсутствие текста карточек.
4. Замеры: видимость правки файла, replay синтетических 50k событий на 5k карточек в Chromium, due после сессии против replay в Node; время пересборки реального репозитория. Больше 1.5 с — инкрементальная сборка по файлам в `content-fs` (D5).
5. Ревью дизайна по DESIGN.md skill `impeccable`; замечания исправлены или записаны в questions.md.

## Затронутые файлы

- `packages/app/e2e/quality.spec.ts`
- `packages/app/src/` — по итогам ревью
- `packages/content-fs/src/bundle.ts` — только если нужна инкрементальная сборка

## Правила

WCAG AA, клавиатура, видимый фокус (NFR-11); без новых сетевых вызовов ([security](../../../../.rules/security.md)).

## Тесты

Всё выше — автоматические e2e, кроме ревью дизайна; результаты замеров — в журнал спеки.
