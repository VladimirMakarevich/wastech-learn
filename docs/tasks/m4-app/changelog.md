# Журнал реализации — M4, приложение

[⌂ index](index.md) · план — [plan/index.md](plan/index.md)

Что сделано по фазам, решения по ходу, замеры для AC-N02 и D5, новые зависимости и их лицензии. Записи только добавляются.

- 2026-11-27 — ADR-0015 принят; фаза 01: пакет `session` (порты, события, правило leech, прогноз интервалов), квиз MCP на нём, `durMs` в событии обрезается на 120 000 мс, как в [review-log](../../content/review-log.md). Новых зависимостей нет: `ts-fsrs` 6.0.1 (MIT) уже стоит у `srs`, у `session` — только для теста.
- 2026-11-27 — фаза 02: `srs/metrics` — true retention young и mature по ответам в фазе review (`reviewRecords` из replay), прогноз нагрузки по учебным дням без симуляции ответов, `comebackStatus` и `comebackDays` для плана возврата. В golden нет журнала, поэтому ручной подсчёт идёт на журнале, собранном в тесте.
- 2026-11-27 — фаза 03: движок сессии в `session` — журнал в памяти с replay по одному review item (items в replay независимы), очередь `srs` на старте и learning steps в ходе сессии без пересборки очереди, `refresh` на внешние изменения, подсказка по рубрике (есть / частично / нет), итоги. В bundle у карточки появилось `created`, чтобы новые карточки в приложении шли в том же порядке, что в квизе; версия bundle — 1. Замер в Node на синтетическом журнале 50k событий и 5k карточек: старт сессии (полный replay и очередь) ≈ 0.94 с, оценка ≈ 3 мс (медиана). Долг: бенчмарк M2 `buildQueue` на 5k карточек держится около 50 мс и изредка задевает бюджет при параллельном прогоне тестов.
- 2026-11-27 — фаза 04: `core/search` сериализует индекс в строку (`serialize`) и восстанавливает его (`loadSearchIndex`) с теми же настройками; `buildBundle` кладёт её в `searchIndex`. Снапшот golden проверяет bundle без индекса: данные MiniSearch проверяются тем, что индекс отвечает, а не байтами. Новый код ошибки `search-index-invalid` с сообщениями на трёх языках.
- 2026-11-27 — фаза 05: `watchRepository` в `content-fs` на рекурсивном `fs.watch` с задержкой 200 мс; своя дозапись узнаётся по размеру файла после записи (`ownAppend`). Без новых зависимостей.
- 2026-11-27 — фаза 06: пакет `server` (Hono) и `wastech-learn serve --content <путь> [--port] [--no-open]`, порт по умолчанию 4747. Зависимости: `hono` 4.13.22 (MIT, без зависимостей) и `@hono/node-server` 2.1.11 (MIT, без зависимостей) — те же версии уже были в дереве через `@modelcontextprotocol/sdk`, дублей нет. `cli` импортирует `server` (его запускает `serve`), граница в ESLint описана. Корень `/` отдаёт приложение после фазы 07, до неё — `404`. Замер пересборки bundle реального `wastech-learn-content` (3 темы, 30 карточек): 160–300 мс, инкрементальная сборка не нужна.
- 2026-11-27 — фаза 07: пакет `app` (Angular 22.3.0, standalone, zoneless, `@angular/build`), маршруты экранов-заглушек, сборка в `packages/app/dist/browser`, которую раздаёт `serve`; HTML приходит со строгим CSP. Lint: angular-eslint для TS и встроенных шаблонов с правилами доступности, Stylelint и Prettier, `typecheck` = `tsc -b` + `ngc` со `strictTemplates`. Аналитика Angular CLI выключена в `angular.json`. E2E: Playwright с global setup (копия golden, журнал-фикстура с сидом, `serve --port 0`), аудит сети в каждом сценарии, job `e2e` в CI. Ссылки `references` в tsconfig теперь указывают на файлы: загрузчик Playwright не понимает ссылку на папку. Зависимости и лицензии: `@angular/{core,common,compiler,forms,platform-browser,router,cdk,build,cli,compiler-cli}` 22.3.0 (MIT), `rxjs` 7.8.2 (Apache-2.0), `tslib` 2.9.1 (0BSD), `angular-eslint` 22.8.0 (MIT), `@playwright/test` 1.62.0 (Apache-2.0; версия под Chromium, который уже лежит в локальном кэше), `@axe-core/playwright` 4.14.1 и `axe-core` (MPL-2.0, только в тестах, приложение их не включает). Скрипты установки (`esbuild`, `lmdb`, `msgpackr-extract`, `@parcel/watcher`) npm не запускает: сборка работает без них.
- 2026-11-27 — фаза 08: слой данных (`HttpReviewStore` держит неотправленные события в памяти и `localStorage` и досылает с нарастающей задержкой; `loadEvents` отдаёт журнал сервера вместе с ожидающими), API с разбором ответов на границе, SSE с переподключением, i18n по образцу `wastechlab-mobile-template` (signals, pipe `t`, `Intl.PluralRules`, тесты паритета, плюралов, тона и аудита литералов), стили Evening Glass из прототипа (комментарии переведены, демо-правила убраны), Inter с `OFL.txt` и CSS KaTeX локально, компоненты `ui/`, клавиши с `g h` и `/`, оболочка. Найдено и исправлено: `/api/status` отдавал разобранный конфиг, который схема файла не принимает, — теперь сервер отдаёт форму файла (`loadConfigSource`). У `core` появилась браузерная точка входа, у `core`, `srs`, `session` — `sideEffects: false`: сборка приложения — 19 файлов вместо 468. Bundle в приложении проверяется по версии и форме списков: отдельной Zod-схемы bundle в `core` нет, его собирает та же версия, что раздаёт приложение.
- 2026-11-27 — фаза 09: экран Review по контракту DESIGN.md (вопрос на месте, уверенность и «Показать ответ» в стеклянной панели, ответ, объяснение и схема, четыре оценки с интервалами из `session.preview` и `aria-keyshortcuts`, контекст справа: память сессии, состояние FSRS, ключевая идея, файл), панель сессии в тулбаре, `u`/`Ctrl+Z`, `o`, `e`, `!`, `b`, «изменена» и сброс, озвучка `pl-PL` через Web Speech. В bundle у карточки появились `file` и `reverseHtml` (обратная сторона `vocab` без примера, общей с квизом функцией). Подсказка по рубрике предлагает «С трудом», если всё обязательное есть, но ответ занял больше двух обычных времён. E2E: 20 карточек только клавиатурой с видимым фокусом на каждом шаге; медиана от оценки до следующей карточки < 50 мс (AC-N02, первая часть). Сценарии e2e делят журнал, поэтому часы каждого ставятся после последнего записанного события.
- 2026-11-27 — фаза 10: Home (очередь дня и минуты из `srs`, новые по доменам, прогноз на 7 дней, три кнопки сессии с `Enter`, темы по доменам со строкой точек памяти и due; после паузы больше 3 дней — план возврата без цвета и без слов о пропусках) и Session end (число и минуты, true retention ответов в фазе review, забытое при уверенности «точно» со ссылкой на Browser, прогноз на завтра, «На главную» и «Ещё N минут»). Общий replay журнала для экранов библиотеки — `Library`: считается лениво, экран Review его не трогает. E2E сверяют числа Home с очередью `srs`, посчитанной в Node на той же копии.
- 2026-11-27 — фаза 11: Topic (оглавление с заголовками секций на языке интерфейса, текст на языке темы, `Self-check` по одному вопросу, карточки темы с R и due, материалы, «Открыть в VS Code») и Browser (поиск по индексу из bundle без запросов к серверу, фильтры домена, темы, тега, типа, статуса, leech и «изменена», таблица с R, due, забываниями и последней оценкой, боковая панель с `e`, `o` и возвратом отложенной карточки, список карточек из итогов сессии). В golden нет формул, поэтому KaTeX проверяется на копии прогона после правки summary. `core/search` разделён на загрузку (`load.ts`, только MiniSearch) и построение: браузерная точка входа больше не тянет парсер Markdown. Долг: пространство имён `z` из `zod` занимает ≈ 490 КБ основного чанка приложения (все локали); предупреждающий бюджет сборки поднят до 1 МБ, переход схем `core` на `zod/mini` — отдельная задача.
- 2026-11-27 — фаза 12: Stats (один подписанный график нагрузки на 30 дней с выделенным сегодня и приглушёнными выходными; true retention молодых и зрелых карточек за 7 и 30 учебных дней, цель — desired retention из конфига) и Settings (язык, тема и длительность короткой сессии в `localStorage`, проверка голоса `pl-PL`; desired retention, лимиты доменов, устройство и путь контента — только показ, со ссылкой на `learn.config.json` в VS Code). E2E: числа Stats совпадают с подсчётом `srs` в Node, настройки переживают перезагрузку, `git status` копии после работы с ними чистый, язык меняется без перезагрузки.
