# Приложение: синхронизация с git и действия над карточками

- **Slug:** `app-sync-and-cards`
- **Статус:** in-progress
- **Создано:** 2026-11-27
- **Владелец:** Vladi Makarevich

## Кратко

Приложение показывает, что в контент-репозитории не закоммичено (индикатор, страница темы, Cards), синхронизирует его с удалённым одной кнопкой (commit только `content/`, `reviews/`, `inbox/`, pull с rebase, push) и позволяет архивировать, возвращать и удалять карточки и архивировать темы. Логика git и записи — в `content-fs` с теми же проверками, что у MCP; сервер тонкий; новую границу фиксирует ADR-0017. Всё локально ([ADR-0016](../../adr/0016-local-only.md)). Работа разбита на 7 фаз.

ADR принят по поручению владельца без отдельного согласования, ревью — в PR.
- 2026-11-27 — фаза 02: `content-fs/git` (`runGit` без оболочки с `LC_ALL=C` и `GIT_TERMINAL_PROMPT=0`, разбор porcelain v2, классификация путей, причины блокировки, `suggestCommitMessage`), `GET /api/git`, событие `git-changed` после любых изменений рабочего дерева и после своей дозаписи, дозапись журнала через общую очередь `Workspace.exclusive`. Решения: `git status` с `GIT_OPTIONAL_LOCKS=0`, чтобы обновление индикатора не ломало коммит владельца на `index.lock`; файлы `content/` вне темы — `area: topic` без `topic` (их коммитит синхронизация); наблюдатель сообщает о любых файлах вне `.git/`, `.cache/`, `node_modules/` как `other`; сообщение коммита всегда называет устройство. Замер на копии golden — `benchmark.test.ts` сервера, бюджет 300 мс.
- 2026-11-27 — фаза 03: `syncRepository` и `pullRepository`, маршруты `POST /api/git/sync` и `/api/git/pull` через очередь `Workspace`; отказ — `409` с `{ code, … }`, кривое тело — `400 body-invalid` с полем. Решения: в коммит идут явные пути синхронизации с `--only`, поэтому застейдженное владельцем вручную в него не попадает; `--cleanup=whitespace`, чтобы строка с `#` не пропадала; любой сбой до push возвращает и коммит, и индекс к состоянию до нажатия (`reset --soft` и `read-tree`), отказ push оставляет коммит; push — явно в `branch.<имя>.merge` своего remote, не по `push.default`. AC-F08b проверен заглушкой ssh, которая отвечает отказом ключа, и `GIT_ASKPASS=false` — сеть не открывается; отдельно — таймаут, который останавливает всю группу процессов. После ревью: пути для `git add` фильтруются по рабочему дереву и индексу (удалённое через `git rm` не ломает синхронизацию), `GIT_LITERAL_PATHSPECS`, счёт полученных коммитов от `HEAD` до upstream, остановленный rebase узнаётся по папкам `rebase-*`; решены AS-Q10…AS-Q12.
- 2026-11-27 — фаза 04: `commitFiles` удаляет файлы в той же транзакции, `applyWrite` и `validateOverlay` принимают удаление (`null`); `deleteCard`, `restoreCard` (текст и строка индекса из `HEAD`), `setCardStatus` через `updateCard`, `setTopicStatus`; обе функции очереди `session` пропускают карточки архивных тем (квиз MCP и приложение согласованы); маршруты карточек и тем вынесены с маршрутами git из `server.ts` в `git-routes.ts` и `content-routes.ts`. Решены AS-Q13, AS-Q14; новый код ошибки `nothing-to-restore` с текстами в каталоге `core`. После ревью: тесты отката удаления в транзакции и хелперов ссылок в `core`; `card-not-found` и `topic-not-found` — `404`, остальные коды — `409`; отмена удаления проверяет `id` во всём контенте.
