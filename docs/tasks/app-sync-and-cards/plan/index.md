# План реализации — приложение: синхронизация с git и действия над карточками

[⌂ спека](../index.md) · строит [design.md](../design.md) к [acceptance-criteria.md](../acceptance-criteria.md)

## Стратегия

Сначала граница: ADR-0017, правила и схемы (01). Затем серверная логика двумя ветками: git — сначала только чтение состояния (02), потом синхронизация (03); записи карточек и тем (04) от git не зависят и могут идти параллельно с 02–03. Приложение строится поверх: синхронизация в оболочке (05), затем действия над карточками и темами (06). Приёмка и документы — последними (07). Критический путь — 01 → 02 → 03 → 05 → 06.

## Общее для всех фаз

- **Коммиты:** Conventional Commits (`feat(content-fs): …`, `feat(server): …`, `feat(app): …`, `docs: …`), только после «да» владельца, без строк об агенте.
- **Тесты:** временные копии golden и временные git-репозитории с bare-удалённым, никогда не настоящий контент; сеть не открывается.
- **Документы:** фаза, которая меняет поведение или границу, обновляет [components](../../../architecture/components.md) и правила в том же коммите; фаза 07 сводит остальное.
- **Зависимости:** новых нет (design, definition of done).
- **DoD:** [definition-of-done.md](../definition-of-done.md).
