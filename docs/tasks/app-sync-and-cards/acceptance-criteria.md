# Критерии приёмки — приложение: синхронизация с git и действия над карточками

[⌂ index](index.md) · требования — [requirements.md](requirements.md) · дизайн — [design.md](design.md)

«Репо» — временная копия golden, превращённая в git-репозиторий с первым коммитом и bare-удалённым во временной папке (upstream настроен); «второй клон» — ещё один клон того же bare. «Контракт» — маршрут через `app.request()`; «e2e» — Playwright (Chromium) на `wastech-learn serve` над репо.

## Функции

| # | Дано → когда → тогда | Проверка |
| --- | --- | --- |
| AC-F01 | В репо изменена карточка, удалена другая, добавлен файл темы, дописан журнал, создан `.codex/config.toml` → `GET /api/git` отдаёт пять записей с верными `change` и `area` (`card`, `card`, `topic`, `reviews`, `other`), темой и `id` карточки; `ahead`/`behind` = 0 | unit `status.ts` + контракт |
| AC-F02 | Правка файла в репо → индикатор в боковой панели показывает число изменений не позже чем через 2 с; коммит в репо снаружи, возврат на вкладку → индикатор «всё сохранено» | e2e |
| AC-F03 | Новая карточка и правка summary темы → на Topic блок «Не закоммичено» с двумя файлами и видом изменения; у другой темы блока нет | e2e |
| AC-F04 | Изменённая карточка → в Cards пометка в строке; фильтр «не закоммичено» оставляет только её | e2e |
| AC-F05 | Изменения в `content/` и `.codex/` → панель синхронизации: первые в «войдёт», второе в «не войдёт»; сообщение по умолчанию совпадает с `message.ts` и редактируется | e2e + unit `message.ts` |
| AC-F06a | «Синхронизировать» с изменёнными журналом и карточкой → в bare новый коммит с этим сообщением и ровно этими путями; `.codex/config.toml` остаётся незакоммиченным; итог «отправлено: 1 коммит» | unit `sync.ts` + e2e |
| AC-F06b | Нечего коммитить, во втором клоне отправлен коммит → «Синхронизировать» получает его и ничего не коммитит; итог называет полученное | unit `sync.ts` |
| AC-F07 | Во втором клоне отправлена новая карточка; в репо есть незакоммиченная правка → «Получить» приносит карточку, правка на месте | unit `sync.ts` + e2e |
| AC-F08a | Одна карточка по-разному изменена и отправлена во втором клоне и закоммичена в репо → «Синхронизировать» отвечает `conflict` с этим файлом; после ответа нет rebase в процессе, `HEAD` и рабочее дерево как до pull, журнал не изменён | unit `sync.ts` + контракт |
| AC-F08b | Удалённый требует пароль (`GIT_ASKPASS` в тесте завершает с ошибкой) → ответ `auth-required` не позже таймаута, процесс git не висит | unit `sync.ts` |
| AC-F08c | Нет upstream; detached HEAD; файл `.git/MERGE_HEAD` → `GET /api/git` отдаёт `blocked` с причиной, кнопки недоступны, `POST /api/git/sync` → `blocked` | unit + контракт + e2e |
| AC-F09 | После AC-F07 новая карточка видна в Cards и в очереди Home без перезапуска сервера | e2e |
| AC-F10 | Сессия из 3 оценок, оценки не закоммичены → на итогах строка о неотправленных оценках и кнопка; после синхронизации строки нет; сессия без оценок → строки нет | e2e |
| AC-F11a | `a` на Review → в файле карточки `status: retired`, карточка ушла из сессии и очереди Home, тост с «Вернуть»; «Вернуть» → `active`, карточка снова в очереди с прежней историей | e2e |
| AC-F11b | В Cards фильтр «Архив» показывает карточку из AC-F11a; кнопка «Вернуть» в боковой панели возвращает её | e2e |
| AC-F12a | Удаление `draft` и карточки без событий → простое подтверждение, файл удалён, ссылки в `index.md` нет, `check` — 0 ошибок | unit `deleteCard` + e2e |
| AC-F12b | Удаление карточки с историей → подтверждение с текстом о сохранённой истории; основное действие — «В архив»; после подтверждения файл удалён, строки журнала не изменились | e2e |
| AC-F12c | «Отменить удаление» до коммита → файл совпадает с `HEAD`, ссылка в `index.md` на месте, другие незакоммиченные правки `index.md` сохранены | unit `restoreCard` |
| AC-F13 | Тема → «В архив» на Topic → `status: archived` в `index.md`; её карточек нет в очереди приложения и в `quiz_next` MCP; «Вернуть» → снова есть | unit `session` + e2e |
| AC-F14a | Смена статуса, которая ломает проверку (подменённый файл с ошибкой схемы) → `blocked` с находками, файл не изменён | контракт |
| AC-F14b | Файл карточки изменён на диске после чтения → `content-changed`, правка на диске сохранена | unit |
| AC-F15 | Все новые ключи есть в ru, en и pl; аудит литералов и тона проходит; в сообщениях нет слов вины из списка тестов тона | unit i18n |

## Качества

| # | Критерий | Проверка |
| --- | --- | --- |
| AC-N01a | Git вызывается только через `execFile` без `shell`; сообщение коммита с `; rm -rf`, `$(…)` и `--amend` попадает в коммит как текст, других эффектов нет | unit `run.ts` + `sync.ts` |
| AC-N01b | В коммит синхронизации не попадает ни один путь вне `content/`, `reviews/`, `inbox/` | unit `sync.ts` |
| AC-N01c | Новые не-GET маршруты без своего `Origin` или с не-JSON телом → `403` или `415`, ничего не записано | контракт |
| AC-N01d | Сценарии e2e не открывают соединений, кроме `127.0.0.1` (аудит сети M4); bare-удалённый — путь на диске | e2e |
| AC-N02a | Два одновременных `POST /api/git/sync` (две вкладки) → выполняются по очереди, второй видит результат первого; `index.lock` снаружи → `busy` | контракт + unit |
| AC-N02b | После любого ответа с ошибкой из AC-F08 и AC-F14 `git status` репо совпадает с состоянием до запроса | unit |
| AC-N03 | `GET /api/git` на реальном `wastech-learn-content` — медиана < 300 мс; смена статуса видна в приложении < 2 с | замер, запись в журнал спеки |
| AC-N04 | Индикатор, панель, кнопки и подтверждения работают с клавиатуры, фокус в диалоге заперт и возвращается; axe без `serious` и `critical` в обеих темах | e2e |
