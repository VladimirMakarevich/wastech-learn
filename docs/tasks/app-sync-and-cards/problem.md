# Проблема - приложение: синхронизация с git и действия над карточками

[⌂ index](index.md)

## Проблема, как она поставлена

Слова владельца после приёмки M4 и первой темы M3:

> На странице темы в браузере я бы хотел видеть, что есть какие-то незакоммиченные файлы. Можно ли в браузере добавить кнопку commit and push + pull, чтобы не приходилось постоянно просить агента это делать? А ещё было бы неплохо удалять и архивировать карточки прямо в веб-интерфейсе.

Три желания в одном: видеть состояние git, синхронизироваться одной кнопкой и управлять жизнью карточки из приложения.

## У кого эта проблема

- **Автор** - единственный пользователь. Повторяет в приложении на `127.0.0.1`, захватывает темы в Claude Code и Codex, правит карточки в VS Code, работает на нескольких компьютерах (J-07, J-08). Терминал и git знает, но не хочет держать их в голове после каждой сессии.

## Текущая ситуация

- **Состояние git не видно.** Приложение показывает «изменена» только по `contentHash` карточки относительно последнего повторения, а не относительно коммита. Новая тема или оценки, которые ещё не в git, в интерфейсе ничем не отличаются от закоммиченных.
- **Синхронизация - руками или через агента.** По [sync](../../architecture/sync.md) конец работы - это `git add reviews content && git commit && git push`, начало - `git pull`. Команда `wastech-learn sync` упомянута как «позже», её нет. На практике владелец просит агента закоммитить: после захвата `angular/signals` тема и оценки в `reviews/desk1/` часами лежали незакоммиченными.
- **Архив карточки - только правкой файла.** Статус `retired` есть в схеме, но поставить его можно лишь в VS Code (`e`) или через `update_card` в чате. В приложении есть только «отложить» (`suspend`) и «вернуть» ([FR-214](../../requirements/fr-review.md): retire - Later).
- **Удаление - только удалением файла** в редакторе или терминале, без подсказки, что станет с историей повторений.

## Почему сейчас

- Впереди обкатка M5: 4 недели, не меньше 3 сессий в неделю. Каждая сессия добавляет строки в журнал своего устройства; если их не отправить, другой компьютер их не увидит, а забытый `pull` сдвигает интервалы ([sync](../../architecture/sync.md)).
- Колода растёт со скоростью захвата (R-09). Слабые и устаревшие карточки нужно убирать там, где они попадаются, - на повторении и в Cards, а не отдельным походом в редактор.
- После [ADR-0016](../../adr/0016-local-only.md) облачной синхронизации не будет: git остаётся единственным транспортом между компьютерами, и его стоимость для пользователя стоит снизить.

## Сигналы и факты

- В этой сессии владелец дважды просил агента закоммитить и один раз - запушить; незакоммиченными оставались `content/angular/`, `reviews/desk1/`, обновлённые skills и конфиги.
- В `wastech-learn-content` рядом с контентом лежат файлы, которые коммитятся осознанно: `.codex/`, `.agents/skills/`, `.claude/`, `skills-lock.json`, конфиги mdlint.
- Журнал разделён по `device` и `writer` и объединяется `merge=union` ([ADR-0003](../../adr/0003-append-only-review-log.md)): при pull он не конфликтует, конфликтовать может только контент.

## Ограничения, заданные заранее

- Только локально, на компьютере владельца: сервер на `127.0.0.1`, сеть - только git по его нажатию ([ADR-0016](../../adr/0016-local-only.md), [.rules/security.md](../../../.rules/security.md)).
- Headless-ядро: логика в `content-fs` и `core`, сервер и приложение тонкие ([.rules/architecture.md](../../../.rules/architecture.md)).
- Журнал append-only: строки не меняются и не удаляются ([review-log](../../content/review-log.md)). `retired` не удаляется, `id` не переиспользуется ([cards](../../content/cards.md)).
- Запись контента - с проверкой до записи, как у инструментов MCP ([ADR-0012](../../adr/0012-two-tier-validation.md)).
- Тексты интерфейса на ru/en/pl, спокойные и без чувства вины ([.rules/tone-of-voice.md](../../../.rules/tone-of-voice.md)).
