# Требования - приложение: синхронизация с git и действия над карточками

Номера локальные для спеки: `AS-Fnn` - функции, `AS-Nnn` - качества. В скобках - требования проекта из [docs/requirements](../../requirements/README.md). Экраны - в [screens](../../ux/screens.md), вид - в [DESIGN.md](../../../DESIGN.md).

## Функциональные требования

### Состояние git

- **AS-F01 - состояние репозитория.** Приложение знает про контент-репозиторий: ветку, есть ли upstream, на сколько коммитов он впереди и позади (↑ ↓), и список незакоммиченных путей с видом изменения (новый, изменён, удалён, переименован). Каждый путь отнесён к теме, карточке, журналу повторений или «другое» (всё вне `content/`, `reviews/` и `inbox/`).
- **AS-F02 - индикатор в боковой панели.** Вместо «всё сохранено» - число незакоммиченных изменений и ↑ ↓, если они есть. Нажатие открывает панель синхронизации (AS-F05). Индикатор обновляется не позже чем через 2 с после изменения файлов и при возврате на вкладку (коммит в терминале меняет только `.git/`).
- **AS-F03 - изменения на странице темы.** Topic показывает незакоммиченные файлы этой темы (summary, материалы, диаграммы, карточки) с видом изменения.
- **AS-F04 - изменения в Cards.** Изменённая, новая или удалённая с прошлого коммита карточка помечена в таблице; есть фильтр «не закоммичено».

### Синхронизация

- **AS-F05 - панель синхронизации.** Показывает, что войдёт в коммит (пути в `content/`, `reviews/`, `inbox/`), и отдельно - что не войдёт («другое», коммитится вручную). Поле сообщения коммита заполнено автоматически по составу изменений (например, `chore: reviews and 1 topic from desk1`), его можно изменить.
- **AS-F06 - «Синхронизировать»** (FR-311). Одна кнопка: коммит путей из AS-F05 (если есть что коммитить) → получение изменений с rebase поверх них → отправка. Итог - одна строка: что закоммичено, получено и отправлено.
- **AS-F07 - «Получить».** Отдельная кнопка только для получения изменений, в том числе когда есть незакоммиченные правки.
- **AS-F08 - сбои без потерь.** Если при получении возник конфликт, репозиторий возвращается в состояние до нажатия, а приложение называет файлы и предлагает решить конфликт в VS Code. Если git ждёт пароль или подтверждение, операция не зависает: приложение просит выполнить команду в терминале. Нет upstream, ветка в detached HEAD, rebase или merge уже идёт, нет git - кнопки недоступны, причина названа.
- **AS-F09 - после получения.** Новые темы, правки карточек и чужие события журнала появляются в приложении без перезапуска сервера.
- **AS-F10 - напоминание на итогах.** Если оценки только что завершённой сессии ещё не отправлены, Session end спокойно говорит об этом и даёт кнопку «Синхронизировать». Отправка всегда только по нажатию.

### Карточки и темы

- **AS-F11 - в архив и обратно** (FR-214). Карточку можно перевести в `retired` из боковой панели Cards и из действий на Review; она сразу уходит из очереди, история сохраняется. «Вернуть» переводит её в `active`. Фильтр по статусу в Cards показывает архивные.
- **AS-F12 - удаление.** `draft` и карточку без событий в журнале можно удалить после простого подтверждения. Для карточки с историей основное действие - «В архив»; «Удалить» доступно после подтверждения, которое объясняет: история в журнале останется, карточка из очереди и статистики уйдёт. До коммита удаление видно в изменениях (AS-F03, AS-F04) и его можно отменить.
- **AS-F13 - архив темы.** Тему можно перевести в `archived` и вернуть в `active` со страницы Topic. Карточки архивной темы не попадают в очередь; Home показывает её только по запросу.
- **AS-F14 - запись с проверкой.** Смена статуса и удаление проходят те же проверки, что запись через MCP: если правка ломает файл или ссылки, ничего не записывается, а приложение показывает находки. Правка, сделанная снаружи после того, как приложение прочитало файл, не затирается.

### Язык

- **AS-F15 - тексты.** Все новые подписи, сообщения и подтверждения - на ru, en и pl, спокойные и без вины (не «вы забыли отправить», а «оценки этой сессии ещё не отправлены»).

## Нефункциональные требования

- **AS-N01 (безопасность)** (NFR-03). Сервер по-прежнему только на `127.0.0.1` и принимает изменения только со своей страницы. Git запускается с фиксированным набором аргументов без оболочки; пользовательский текст (сообщение коммита) - только отдельным аргументом. В индекс попадают только пути из AS-F05, никогда «всё сразу». Сеть открывается только git'ом по нажатию; ключи и пароли сервер не видит и не хранит.
- **AS-N02 (целостность)**. Журнал повторений не меняется (append-only). Сбой любой операции оставляет репозиторий в состоянии до неё. Две операции git или записи не идут одновременно, в том числе из двух вкладок.
- **AS-N03 (скорость)** (NFR-05). Состояние git на реальном контент-репозитории считается быстрее 300 мс; смена статуса карточки видна в приложении быстрее 2 с.
- **AS-N04 (доступность)**. Все действия доступны с клавиатуры; подтверждения - модальные диалоги с ловушкой фокуса; axe без нарушений `serious` и `critical` в обеих темах.
- **AS-N05 (тесты)**. Логика git проверяется на временных репозиториях с локальным bare-удалённым; e2e идут без сети.

## Данные и хранение

- Новых форматов нет. Меняются только `status` во front matter карточки (`active` ↔ `retired`) и темы (`active` ↔ `archived`), удаляются файлы карточек. Новых видов событий в журнале нет: архив - это статус файла, а не событие.
- Коммиты создаются в контент-репозитории владельца от его имени (его `user.name` и `user.email`).
- Сервер приложения впервые пишет в Markdown и запускает git - это расширение границы [ADR-0007](../../adr/0007-local-server-phase-1.md), нужен новый ADR.

## Зависимости и допущения

- Контент - git-репозиторий с настроенным upstream; git есть в `PATH`; доступ к удалённому настроен через ssh-agent или credential helper без ввода в терминале.
- Путь записи с проверкой из M3 (`content-fs`, `update_card`) и наблюдение за файлами из M4 (`watchRepository`, SSE) переиспользуются.
- Сейчас очередь отбирает карточки только по статусу карточки; статус темы она не учитывает (нужно для AS-F13).
